# BuildWatch API Contract (v1 draft)

Owner: Member 2 (Backend + Database)
Rule: everyone uses EXACTLY these names. Do not invent new ones.

## 1. Shared values (enums)

Roles: CITIZEN, FIELD_WORKER, ADMINISTRATOR
Case status (in order): REPORTED, UNDER_REVIEW, ASSIGNED, IN_PROGRESS, VERIFICATION_PENDING, RESOLVED, CLOSED
Debris categories: RUBBLE, SAND, BRICKS, CEMENT_BAGS, METAL_RODS (UNKNOWN is internal to AI only)
Public area types: FOOTPATH, ROAD, DRAIN
Severity (set by backend only): 1 = LOW, 2 = MEDIUM, 3 = HIGH, 4 = CRITICAL
Removal status: REMAINS, EXPANDED, REMOVED
Image types: ORIGINAL, FOLLOW_UP

## 2. Case ID
Format BW-YYYY-NNNNN (example BW-2026-00001). Generated by the backend only.

## 3. Decisions still required [DECISION REQUIRED]
- LOCATION_THRESHOLD (proposed 30 metres)
- IMAGE_SIMILARITY_THRESHOLD (proposed 0.75)
- Severity formula (proposed: category weight x area multiplier)

## 4. Endpoints

All responses are JSON unless stated. Errors use: {"error": {"code": "...", "message": "..."}}

| Method | Path | Purpose |
|---|---|---|
| POST | /reports | Create a report (multipart form: image, description, latitude, longitude, public_area_type, reporter_role) |
| GET | /reports | List all cases |
| GET | /reports/{case_id} | One case, includes follow_ups list |
| PUT | /reports/{case_id}/status | Body: { "status": "...", "note": "..." } |
| GET | /reports/{case_id}/history | List of status changes |
| POST | /reports/{case_id}/follow-up | Multipart form: image, note. Returns the follow-up object |
| POST | /reports/{case_id}/verify | Body: { "verified": true, "note": "..." } (administrator only) |
| GET | /dashboard/hotspots | Array of { latitude, longitude, case_count, max_severity } |
| GET | /reports/{case_id}/evidence-report | Returns a PDF file |
| POST | /ai/analyze | Internal use by backend |
